# Shared career facts and role-focused CV views

Website Experience renders all shared company bullets. Its context note separates company PHP/Laravel/realtime work from recent independent AI projects, without assigning unconfirmed project years to a specific employment subperiod.

Experience records now support canonical `bullets: [{id,text}]`. Legacy `highlights` remain readable and are synchronized from canonical bullets during schema validation. Admin editing preserves IDs when editing/reordering text; CV selections reference those IDs, not array positions or copied sentences. Removing a selected bullet is rejected until the CV selection changes. Each CV can use all shared bullets or select/order a subset, including an empty selection to omit a role's bullets. Employment identity and dates always remain shared.

Each CV has editable `sectionOrder`, `projectsHeading`, and `experienceSelections` fields. The AI default places Independent AI Engineering Projects before a shorter Professional Experience. The Senior default places relevant company Experience before Selected Projects and prioritizes frontend, leadership, backend integration and delivery skills. Both HTML/PDF and Markdown use the same selection/order helpers. Neither view presents independent AI projects as company employment.

Website skills use `settings.websiteSkillIds` to show six applied capability groups, each with a short description, keyword list and linked project evidence. Skills support `description`, `projectIds` and `stage` (`applied`/`research`). Research is rendered separately and is not a percentage or claimed proficiency score. CVs still use compact plain text skill groups. Evidence URLs follow the current public locale. Shared evidence/website references are validated and guarded on deletion.

Migration: run `pnpm db:deploy` after merging. The fourth migration in this PR derives initial bullet IDs from each snapshot's actual fact text and preserves existing canonical bullets. Default CV bullet subsets are applied only when source text/IDs exactly match the known originals; custom Experience defaults to its full facts. Existing section settings, custom skill selections, custom summaries and unpublished snapshots are preserved. Skill evidence references are filtered to existing projects. English/Vietnamese snapshots are handled independently, other locales untouched. New English seeds match the migrated default.

Validation: 58 tests cover shared fact edits/reordering, removal protection, invalid references, role-specific HTML/Markdown ordering, legacy input, locale-aware skill evidence, both PDF exports and existing application behavior. TypeScript and production build pass. Both updated English CV samples are two A4 pages and all four pages were visually inspected. Website skills previews were inspected at desktop and 375px, with a mobile overflow check. Local PGlite/PostgreSQL migration tests verify seed equivalence, custom facts/summary/skills, null publication, unrelated locales and idempotence. Production data was not modified.
